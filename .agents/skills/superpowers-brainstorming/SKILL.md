# Superpowers: Brainstorming & Requirements Clarification

This skill facilitates rigorous exploration of requirements, UX flow options, architectural trade-offs, and design choices before writing any code.

## When to Use
- **Mandatory before non-trivial coding**.
- Whenever requirements are ambiguous, open-ended, or have multiple valid implementation paths.
- Designing new modules, UI dashboards, or API endpoints.

## Procedure

1. **Clarify Intent**:
   - Understand the core problem the user wants solved.
   - Formulate 2–3 viable approaches with clear pros and cons.
2. **Interactive Alignment**:
   - Ask clarifying questions or propose options using concise choices.
   - Address edge cases (e.g., offline mode, network failure, invalid user input).
3. **Draft Acceptance Criteria**:
   - Define unambiguous definition-of-done criteria before coding starts.
   - Hand off to `prd-creator` or `writing-plans`.
